# API reference

> This reference describes the supported public surface for React Native, Electron renderer, and Electron main/core usage. TypeScript declarations generated by the current package remain authoritative for exact generic inference.

## Package entry points

| Import                            | Environment                                                     | Contents                                                                         |
| --------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `@lwjlol/view_model`              | non-React/core                                                  | Same public core surface as `@lwjlol/view_model/core`.                           |
| `@lwjlol/view_model/core`         | React Native plain owners, Electron main, tests, shared modules | ViewModel classes, Specs, Runtime, Binding, types, and errors.                   |
| `@lwjlol/view_model/react-native` | React Native                                                    | All core exports plus the React Native Scope, hooks, and AppState adapter.       |
| `@lwjlol/view_model/electron`     | Electron renderer                                               | All core exports plus the Electron renderer Scope, hooks, and lifecycle adapter. |

The package intentionally does not export `@lwjlol/view_model/react`. The internal React implementation is shared only by the two platform adapters and is not a general React Web contract.

## Core architecture

The Runtime is the application DI and lifecycle boundary. Bindings are owners inside that Runtime. A platform Scope merely creates a React Binding and supplies it to platform hooks.

```text
ViewModelRuntime
├── ViewModelBinding (plain owner)
├── ViewModelBinding (React Scope owner)
└── ViewModel generation
    ├── external root Binding sources
    └── ViewModelBinding (generation-owned dependency owner)
        └── child generation
            └── mirrored external root Binding sources
```

Each parent generation has one stable dependency Binding. Its current external root Binding sources are mirrored to resolved children, including later source additions and removals. Direct ownership and every parent path are counted independently.

Keyed identity, dependency propagation, and Runtime pause are all Runtime-local. No managed identity is shared across different Runtime objects or Electron processes.

## `ViewModel`

All managed modules extend the abstract `ViewModel` base class:

```ts
import { ViewModel, viewModelSpec } from '@lwjlol/view_model/core';

class CounterViewModel extends ViewModel {
  public count = 0;

  public increment(): void {
    this.update('counter.increment', () => {
      this.count += 1;
      this.notifyListeners();
    });
  }
}

export const counterSpec = viewModelSpec(CounterViewModel, () => new CounterViewModel());
```

### Public properties

#### `version: number`

The current notification version. Every call that passes the alive guard
increments it before delivery, even if a listener later throws.

#### `isDisposed: boolean`

Whether the current generation has permanently ended. Most ViewModel operations throw `ViewModelDisposedError` after disposal.

#### `isPaused: boolean`

Whether the owning Runtime is currently paused. Pause affects all activated generations in that Runtime.

#### `viewModelBinding: ViewModelBinding`

The stable dependency Binding attached to this ViewModel generation. Use it in getter-based module dependencies after the instance has been attached and activated:

```ts
class CheckoutViewModel extends ViewModel {
  private get cart(): CartViewModel {
    return this.viewModelBinding.read(cartSpec);
  }
}
```

Access before Runtime attachment throws `UnmanagedViewModelError`. Access after disposal throws `ViewModelDisposedError`. Do not access dependency getters from constructors, React render, JSX, or selectors.

### Subscription

#### `subscribe(listener): ViewModelDispose`

Installs a direct listener for ordinary ViewModel notifications and returns an unsubscribe function:

```ts
const unsubscribe = viewModel.subscribe(() => {
  refreshExternalConsumer();
});

unsubscribe();
```

Direct subscriptions are not owned by a Binding and are not delayed by Runtime pause. Keep and invoke the returned cleanup, or register it with the lifetime of another managed owner.

Use `ViewModelBinding.listen` when the subscription should be owned and cleaned up by a Binding.

### Protected notification methods

#### `notifyListeners(action?: unknown): void`

Opens or reuses a propagation transaction before incrementing `version` and notifying direct subscribers. The transaction encloses the entire synchronous cascade, including dependency bubbling and nested synchronous `notifyListeners` calls.

Binding callbacks are deduplicated by `(owner Binding identity, callback identity)`. The same callback reached repeatedly through one Binding runs once, while two different Bindings that reuse that callback each run it once. A parent generation bubbles at most once per transaction. A later microtask or Promise continuation starts a new transaction.

Listener failures are collected and rethrown as `AggregateError`.

#### `update<TResult>(action: unknown, mutation: () => TResult): TResult`

Associates a diagnostic action with synchronous notifications emitted inside `mutation`. It restores an outer action after nested calls and returns the mutation result.

`update` does **not** call `notifyListeners` automatically:

```ts
this.update('profile.rename', () => {
  this.name = nextName;
  this.notifyListeners();
});
```

The action scope is synchronous. Do not expect it to remain active after an awaited asynchronous continuation; pass an explicit action to the later `notifyListeners` or use `StateViewModel.setState`/`updateState`.

#### `addDispose(dispose: ViewModelDispose): ViewModelDispose`

Registers cleanup for generation disposal. Cleanup functions run after `onDispose`, in reverse registration order. The returned function removes that cleanup registration without executing it.

```ts
protected override onCreate(): void {
  const unsubscribe = nativeEvents.subscribe(this.handleNativeEvent);
  this.addDispose(unsubscribe);
}
```

#### `assertAlive(): void`

Allows subclasses to apply the standard disposed-generation guard to their own methods.

### Lifecycle hooks

Subclasses may override:

```ts
protected onCreate(): void;
protected onBind(bindingId: string): void;
protected onUnbind(bindingId: string): void;
protected onPause(): void;
protected onResume(): void;
protected onDependencyNotify(child: ViewModel): void;
protected onDispose(): void;
```

- `onCreate` runs once at the first committed acquire.
- `onBind` runs when the first ownership source for a Binding id reaches the generation.
- `onUnbind` runs only after the last source for that id is removed. Direct ownership and multiple parent paths are source-aware and counted independently.
- `onPause` and `onResume` track Runtime-wide pause transitions.
- `onDependencyNotify` runs before a watched child notification is re-emitted by the parent.
- `onDispose` runs once when the generation permanently ends.

## `StateViewModel<TState>`

`StateViewModel` extends `ViewModel` with an immutable state snapshot and state-diff listeners.

```ts
interface SessionState {
  readonly userId: string | undefined;
  readonly loading: boolean;
}

class SessionViewModel extends StateViewModel<SessionState> {
  public constructor() {
    super({ userId: undefined, loading: false });
  }

  public setLoading(loading: boolean): void {
    this.updateState((current) => ({ ...current, loading }), 'session.loading');
  }
}
```

### Constructor

```ts
protected constructor(
  initialState: TState,
  equals?: (left: TState, right: TState) => boolean,
)
```

The default equality is `Object.is`. There is no global equality configuration.

### `state: TState`

Returns the current immutable state snapshot.

### `subscribeState(listener): ViewModelDispose`

Subscribes directly to state transitions. The listener receives:

```ts
interface StateChange<TState> {
  readonly current: TState;
  readonly previous: TState;
}
```

The returned unsubscribe function must be managed explicitly. Direct state listeners are not delayed by Runtime pause.

Use `ViewModelBinding.listenState` or `listenStateSelect` for Binding-owned state side effects.

### `setState(nextState, action?): boolean`

Protected. Replaces the state when the configured equality returns false, notifies `subscribeState` listeners, and then notifies ordinary ViewModel listeners. Returns `true` when a transition occurred and `false` when it was suppressed as equal.

### `updateState(updater, action?): boolean`

Protected. Computes the next state from the current state and delegates to `setState`.

## `ViewModelSpec<T>`

A Spec combines an explicit runtime ViewModel type, a builder, and lifecycle policy. Passing the class explicitly is the recommended identity contract.

### Creation

```ts
const spec = new ViewModelSpec(ExampleViewModel, () => new ExampleViewModel(), {
  key: 'example',
  aliveForever: false,
  debugLabel: 'ExampleViewModel',
});
```

The helper is equivalent and normally preferred:

```ts
const spec = viewModelSpec(ExampleViewModel, () => new ExampleViewModel(), {
  key: 'example',
});
```

The builder-only overload remains available as a compatibility fallback:

```ts
const legacySpec = viewModelSpec(() => new ExampleViewModel());
```

### `ViewModelSpecOptions`

```ts
interface ViewModelSpecOptions {
  readonly key?: ViewModelKey;
  readonly tag?: unknown;
  readonly aliveForever?: boolean;
  readonly debugLabel?: string;
}
```

- `key` makes the Spec identity shareable by Bindings in one Runtime. Use it with an explicit ViewModel class when independently created Specs must share.
- `tag` is a grouping label for advanced cached lookup. It is compared with `Object.is` and does not participate in identity.
- `aliveForever` skips ordinary zero-owner disposal and requires an explicit key.
- `debugLabel` is used in diagnostics and generation descriptions; it is not identity.

### Identity properties

```ts
readonly type: ViewModelType<T> | undefined;
readonly token: symbol;
readonly builder: ViewModelBuilder<T>;
readonly key: ViewModelKey | undefined;
readonly tag: unknown;
readonly aliveForever: boolean;
readonly debugLabel: string;
```

Runtime identity is:

```text
explicit type + no key = ViewModel class inside one Binding
explicit type + key    = ViewModel class + key inside one Runtime
builder-only fallback  = unique Spec token under the same key/no-key scopes
```

TypeScript generic types do not exist at runtime, so `ViewModelSpec<T>` cannot recover `T` by itself. Separate Specs that pass the same explicit class and key share one keyed generation in a Runtime. Each independently created builder-only base Spec instead receives a unique token, even if its builder and key look identical. Keep builder-only Specs stable at module scope and prefer the explicit type overload for shared identity.

For an explicit type Spec, the builder result is checked at runtime and must be an instance of that type or one of its subclasses. The identity class may be abstract and may have a protected constructor.

### `withKey(key): ViewModelSpec<T>`

Returns a new Spec wrapper with the supplied key while preserving the original explicit type/fallback token, builder, tag, retention option, and debug label.

```ts
const baseSpec = viewModelSpec(EditorViewModel, () => new EditorViewModel());
const primaryEditorSpec = baseSpec.withKey('primary-editor');
```

The builder still accepts no arguments. `withKey` changes identity; it does not inject the key into the constructor.

## `ViewModelRuntime`

`ViewModelRuntime` is the application-level managed object graph and maximum sharing boundary.

### State

```ts
readonly isDisposed: boolean;
readonly isPaused: boolean;
```

### `createBinding(options?): ViewModelBinding`

Creates a plain owner Binding:

```ts
const runtime = new ViewModelRuntime();
const binding = runtime.createBinding({
  id: 'application-bootstrap',
  onUpdate: () => refreshOwner(),
});
```

`ViewModelBindingOptions` contains an optional diagnostic `id` and an optional broad `onUpdate` callback used by imperative `watch` ownership.

Prefer `runtime.createBinding` over calling the Binding constructor directly.

### `pause(token?: unknown): void`

Adds a Runtime-wide pause reason. The first token transitions all activated generations to paused and calls `onPause`.

Calling `pause()` without a token uses one shared default token, so repeated default calls do not create a counter. Independent sources should provide independent stable token objects.

### `resume(token?: unknown): void`

Removes one pause reason. The Runtime resumes only after the last token is removed, then calls `onResume` and flushes coalesced Binding callbacks.

Removing a missing token is a no-op. Calling `resume` after Runtime disposal is also a no-op.

### `recycle(target): number`

```ts
runtime.recycle(viewModel);
runtime.recycle(spec);
```

Force-disposes matching generations and returns the number successfully recycled.

- a ViewModel target selects one concrete generation;
- a Spec target selects every current handle with the same runtime identity and key;
- independently created explicit-type Specs can therefore select the same keyed generation, while builder-only Specs match by their fallback token;
- an unkeyed Spec can therefore match one private generation per Binding;
- current owners and `aliveForever` do not prevent recycle.

Owner callbacks observe generation disposal and resolve a fresh generation on the next hook/snapshot access.

### `dispose(): void`

Idempotently ends the Runtime and force-disposes every remaining generation, including `aliveForever` instances. Later acquisition fails with `ViewModelRuntimeDisposedError`.

For a caller-owned Runtime, dispose owner Bindings first and the Runtime last.

## `ViewModelBinding`

A Binding represents one owner inside a Runtime.

### Construction and state

```ts
const binding = runtime.createBinding({ id: 'owner-id' });

binding.id;
binding.runtime;
binding.isDisposed;
```

React application code normally receives a Binding through platform Scope context. Electron main, bootstrap code, services, and tests create plain Bindings explicitly.

When a parent ViewModel resolves a child through its stable dependency Binding, the Runtime creates a parent-to-child lifetime edge and mirrors every current external root Binding source from the parent to the child. Later root acquisitions and releases remain synchronized. A direct child owner and each parent path contribute separate sources, so removing one path does not prematurely call `onUnbind` or dispose the child.

### `read(spec): T`

Resolves or creates the generation and acquires it for this Binding without subscribing the Binding's ordinary update callback.

```ts
const session = binding.read(sessionSpec);
await session.restore();
```

Inside a parent ViewModel, `read` creates a parent-to-child lifetime edge without bubbling ordinary child notifications.

### `watch(spec, listener?): T`

Resolves, acquires, and marks the entry for ordinary update delivery:

```ts
const model = binding.watch(modelSpec);
```

When the Binding was created with `onUpdate`, ordinary notifications call that callback. An optional direct listener may also be supplied:

```ts
binding.watch(modelSpec, () => {
  refreshOwner();
});
```

The optional listener remains registered for the current generation until that generation or the Binding is disposed; `watch` does not return a per-listener unsubscribe. Do not call this overload repeatedly from render-like or transient code.

Inside a parent ViewModel, `watch` also bubbles child notifications through `onDependencyNotify(child)` and then notifies the parent.

### Advanced cached lookup

Normal dependency injection should retain a Spec and use `read(spec)` or `watch(spec)`. Cached lookup is an advanced escape hatch for intentionally querying a generation that another path has already created:

```ts
type ViewModelCacheTarget<T extends ViewModel> = ViewModelType<T> | ViewModelSpec<T>;

interface ViewModelCacheLookup {
  readonly key?: ViewModelKey;
  readonly tag?: unknown;
}

interface ViewModelBinding {
  readCached<T extends ViewModel>(
    target: ViewModelCacheTarget<T>,
    lookup?: ViewModelCacheLookup,
  ): T;
  watchCached<T extends ViewModel>(
    target: ViewModelCacheTarget<T>,
    lookup?: ViewModelCacheLookup,
  ): T;
  maybeReadCached<T extends ViewModel>(
    target: ViewModelCacheTarget<T>,
    lookup?: ViewModelCacheLookup,
  ): T | undefined;
  maybeWatchCached<T extends ViewModel>(
    target: ViewModelCacheTarget<T>,
    lookup?: ViewModelCacheLookup,
  ): T | undefined;
  readCachesByTag<T extends ViewModel>(target: ViewModelCacheTarget<T>, tag: unknown): T[];
  watchCachesByTag<T extends ViewModel>(target: ViewModelCacheTarget<T>, tag: unknown): T[];
}
```

The target supplies an explicit ViewModel class identity or a Spec identity; the lookup object selects the cached key/tag. A target Spec's own key and tag are not implicit lookup options. An exact key match has priority. If that key misses and a tag is present, lookup falls back to the most recently registered matching target/tag. Without a key, the single-value methods return the most recently registered matching target, filtered by tag when supplied. Tag comparison uses `Object.is`.

These methods are lookup-only: they never run a builder and never create a missing generation. `readCached` and `watchCached` throw `ViewModelSpecError` on a miss; their `maybe` variants return `undefined`. The tag batch methods return every match, or an empty array.

A cache hit is not a borrowed unmanaged reference. It acquires the generation for this Binding, mirrors parent ownership sources, and creates the same parent-to-child lifetime edge as Spec-based resolution. The `read` variants do not deliver or bubble ordinary ViewModel notifications. The `watch` variants do, while all variants still observe disposal/recycle through Binding ownership.

### Binding-owned side-effect listeners

```ts
interface ViewModelBinding {
  listen<T extends ViewModel>(
    spec: ViewModelSpec<T>,
    onChanged: ViewModelListener,
  ): ViewModelDispose;

  listenState<TState>(
    spec: ViewModelSpec<StateViewModel<TState>>,
    onChanged: StateListener<TState>,
  ): ViewModelDispose;

  listenStateSelect<TState, TSelection>(
    spec: ViewModelSpec<StateViewModel<TState>>,
    selector: (state: TState) => TSelection,
    onChanged: StateListener<TSelection>,
    equals?: Equality<TSelection>,
  ): ViewModelDispose;
}
```

Each method resolves through its Spec, acquires the generation without broad `watch` propagation, and installs a direct side-effect listener that is not delayed by Runtime pause. `listenStateSelect` calls `onChanged` only when the selected value changes; its equality defaults to `Object.is`.

The Binding automatically removes these listeners when either the Binding or the generation handle is disposed/recycled. The returned disposer can remove the listener earlier and is safe to call more than once; it removes only that subscription and does not release the Binding's generation ownership. Register listeners once in an owner lifecycle such as `onCreate`; do not register them from a repeatedly evaluated getter or React render.

### `dispose(): void`

Idempotently removes all subscriptions owned by the Binding and releases every acquired generation. Normal zero-owner cleanup is deferred to a microtask and can be cancelled by an immediate reacquire.

Using resolution, cached lookup, listener, or framework adapter methods after disposal throws `ViewModelBindingDisposedError`.

### Framework adapter methods

The exported class contains methods marked `@internal` for the platform hook implementation:

```ts
prepare(spec): T;
subscribe(spec, mode, listener): ViewModelDispose;
getSnapshot(spec, mode): string;
```

- `prepare` may construct a pure provisional object without acquiring it.
- `subscribe` performs the commit-safe acquire and installs one hook subscription.
- `getSnapshot` exposes version/generation identity to `useSyncExternalStore`.

Normal application code should not build custom React integration on these methods. Use the supported React Native or Electron platform hooks.

## React hooks

Both platform entry points export the same hook API.

The Scope is the owner boundary: all hooks below one Scope share its Binding. A hook subscription can unmount independently, but its ViewModel ownership remains until that Scope Binding releases the generation or the Scope is disposed. React render may only prepare a provisional object; commit performs ownership and lifecycle acquisition.

### `useViewModel(spec): T`

Acquires the current Scope Binding during commit and rerenders for ordinary notifications and generation replacement.

### `useReadViewModel(spec): T`

Acquires and retains the generation without rerendering for ordinary notifications. Generation disposal/recycle still changes its snapshot.

### `useViewModelSelector(spec, selector, equals?): Selection`

Subscribes to ViewModel notifications but returns only the selected value. The default equality is `Object.is`.

The selector receives the ViewModel, not only `StateViewModel.state`, so it can select any pure exposed field. It must not mutate, subscribe, perform I/O, or resolve child dependencies.

### `useViewModelRuntime(): ViewModelRuntime`

Returns the current platform Scope Runtime. Intended for infrastructure and advanced integrations.

### `useViewModelBinding(): ViewModelBinding`

Returns the current Scope Binding. Do not call imperative Binding resolution during render.

### Hook types

```ts
type ViewModelSelector<T extends ViewModel, Selection> = (viewModel: T) => Selection;

type ViewModelEquality<Selection> = (previous: Selection, next: Selection) => boolean;
```

## React Native API

`@lwjlol/view_model/react-native` re-exports all core symbols and adds the following.

### `ViewModelScope`

```ts
interface ViewModelScopeProps extends PropsWithChildren {
  readonly runtime?: ViewModelRuntime;
  readonly appState?: ReactNativeAppState;
  readonly lifecycle?: ViewModelLifecycleSource;
}
```

- without an injected/parent Runtime, the Scope creates and owns one;
- a nested Scope reuses its parent Runtime by default and creates a new Binding;
- `appState` defaults to React Native `AppState`;
- an explicit `lifecycle` replaces the AppState lifecycle for that Scope;
- lifecycle pause affects the entire selected Runtime.

### `createReactNativeAppStateLifecycleSource(appState)`

Converts the minimal React Native AppState interface into a `ViewModelLifecycleSource`. Only `currentState === 'active'` is active; every other value is inactive.

### React Native lifecycle types

```ts
interface ReactNativeAppStateSubscription {
  remove(): void;
}

interface ReactNativeAppState {
  readonly currentState: string | null;
  addEventListener(
    type: 'change',
    listener: (state: string) => void,
  ): ReactNativeAppStateSubscription;
}

interface ViewModelLifecycleSource {
  isActive(): boolean;
  subscribe(listener: (active: boolean) => void): () => void;
}
```

## Electron renderer API

## Exported errors

All core errors extend `ViewModelError`:

| Error                           | Meaning                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------- |
| `ViewModelError`                | Base package error.                                                                 |
| `ViewModelDisposedError`        | An operation used a disposed ViewModel generation.                                  |
| `ViewModelRuntimeDisposedError` | An operation required a disposed Runtime.                                           |
| `ViewModelBindingDisposedError` | An operation required a disposed Binding.                                           |
| `ViewModelSpecError`            | A Spec/builder, required cached lookup, or generation preparation invariant failed. |
| `ViewModelDependencyCycleError` | A direct or indirect dependency owner cycle was detected; exposes the cycle path.   |
| `UnmanagedViewModelError`       | `viewModelBinding` was requested before Runtime attachment.                         |

Listener and cleanup failures can also be reported as standard JavaScript `AggregateError` values containing all collected errors.

## Unsupported APIs and environments

The following import is intentionally unavailable:

```ts
// Unsupported: no public Web/React entry point exists.
import { ViewModelScope } from '@lwjlol/view_model/react';
```

The current package does not promise:

- ordinary React Web applications;
- SSR or hydration;
- React Server Components;
- a browser-only lifecycle adapter;
- Flutter APIs such as argument Specs, global initialization/configuration, code generation, or DevTools.

Use only the documented platform entry points and current TypeScript declarations.
